# 🌍 الترجمة الإنجليزية (i18n)

> الحالة: **صفحة الأسعار** مترجمة + مبدّل لغة شغّال. البنية جاهزة للتوسّع.

## ما هو جاهز
- `USE_I18N=True`، `LANGUAGES=[ar, en]`، `LOCALE_PATHS=[locale/]`، `LocaleMiddleware`.
- مبدّل لغة (ع / EN) في هيدر صفحة الأسعار → يمرّ عبر `/i18n/setlang/` (Django).
- اتجاه الصفحة ديناميكي: العربي RTL، الإنجليزي LTR تلقائياً.
- `locale/en/LC_MESSAGES/django.po` (+ `.mo` مُصرَّف) — الترجمات الحالية.

## كيف تضيف ترجمات جديدة

### 1) لُفّ النص في القالب
```django
{% load i18n %}
{% trans "نص ثابت" %}
{% blocktrans with n=var %}نص فيه {{ n }} متغير{% endblocktrans %}
```

### 2) استخرج النصوص وترجمها
لو الأدوات (gettext) متوفّرة على جهازك:
```bash
python manage.py makemessages -l en   # يجمع النصوص في locale/en/.../django.po
# افتح الـ .po وترجم كل msgstr
python manage.py compilemessages       # يبني الـ .mo
```

### 3) بديل بدون gettext (المستخدم هنا)
الـ `.mo` تم توليده بسكربت Python خام (بدون الحاجة لأدوات gettext). لتكرارها بعد
تعديل الـ `.po`، استخدم أي سكربت GNU-MO writer، أو ثبّت gettext وشغّل
`compilemessages`.

## حدود الترجمة الحالية (بصراحة)
- **محتوى قاعدة البيانات** (أسماء الباقات، مزاياها من موديل Plan/Feature) يظهر
  بالعربي دائماً — ترجمة القوالب لا تمسّه. لترجمته: أضف حقول `name_en` على
  Plan/Feature واعرضها حسب اللغة النشطة.
- تُرجمت **صفحة الأسعار** (الهيكل الثابت). باقي الصفحات تُلفّ وتُترجم بنفس الطريقة
  تدريجياً حسب الأولوية.

## التفعيل على السيرفر
الـ `.mo` مُصرَّف ومُلتزم في git، فيصل مع الـ build مباشرة. لا خطوة إضافية —
فقط `docker compose up -d --build`. (لو عدّلت الـ `.po`، أعد توليد `.mo`.)
